\begin{abstract}
\noindent
Standard single-parameter Vietoris--Rips persistent homology on multi-agent point clouds conflates topological features from distinct organisational levels into a single diagram. We present a multi-scale framework addressing this through two methodological contributions: domain-informed hierarchical clustering with validated cutoff distances, decomposing the point cloud by organisational level, and an adaptive Vietoris--Rips filtration scaled to the post-clustering geometry, so that $H_1$ (loop) features are detected consistently across scales. Validation on 10 professional football matches (SkillCorner broadcast tracking, 10~Hz; 43{,}531 frames for the primary match) identifies three $H_0$ regimes --- individual (2.98~m), tactical (12.0~m), and team (30.0~m) --- with 96--100\% cross-epoch validation, and two $H_1$ regimes: individual-scale loops are frequent and transient ($97.0\% \pm 1.5\%$ frame presence), tactical-scale loops are rarer but geometrically persistent ($19.3\% \pm 7.2\%$); team-scale $H_1$ is absent \emph{a priori} from the clustering. Sensitivity analyses confirm robust tactical $H_1$ detection for primary-match cutoffs $\delta$ from $6$~m to $14$~m (near-zero by $\delta=16$~m), insensitivity of headline counts to adaptive percentiles P50--P95, and recovery of geometric cycle representatives for every $H_1$ generator. Across 10 matches (104{,}722 event--topology pairs) topological change correlates coherently with match dynamics: on-ball engagements ($p<0.001$) and quick breaks ($p\le 0.046$) are associated with persistence decreases, and build-up phases ($p<0.001$) with increases. The two scales capture weakly correlated but complementary information (Spearman $\rho = 0.254$). The framework is domain-agnostic and applies to any bounded competitive multi-agent system with spatial tracking data.
\end{abstract}

\section*{Code and data availability}

\paragraph{Data.} All tracking data are from the SkillCorner open broadcast tracking repository \citep{SkillCorner2024}. The ten match IDs analysed in this paper are: primary match \textbf{1996435} (Sydney FC vs Adelaide United, A-League 2024/25), plus 1886347, 1899585, 1925299, 1953632, 2006229, 2011166, 2013725, 2015213, and 2017461. Dynamic event annotations and phase-of-play labels are from the same repository.

\paragraph{Code.} Implementation, analysis pipelines and figure generation scripts are available at \texttt{https://github.com/AroundInteger/Football-TDA}, tagged release \texttt{paper-v1.0} (exact commit hash recorded in the GitHub release notes; to be finalised at submission). The multi-match validation pipeline corresponds to \texttt{03\_football\_analysis/multi\_match\_validation.py} with the \texttt{-{}-skillcorner-only} flag; event correlation is reproduced by \texttt{real\_event\_correlation.py}. Paper v5 revision additions are reproduced by the scripts in \texttt{03\_football\_analysis/paper\_v5\_revisions/}: \texttt{bootstrap\_multi\_match\_ci.py} (\S\ref{sec:scale_complementarity}), \texttt{tda\_native\_distances.py} (Table~\ref{tab:tda_distances}), \texttt{half\_level\_random\_effects.py} (\S\ref{sec:temporal}), \texttt{event\_window\_sensitivity.py} (Table~\ref{tab:event_window}), \texttt{baseline\_vs\_topology.py} (\S\ref{sec:baseline}), \texttt{bilateral\_topology.py} (\S\ref{sec:bilateral}), and \texttt{predictive\_utility.py} (\S\ref{sec:predictive}).

\paragraph{Software stack.} Python 3.11; Ripser.py 0.6.4 \citep{Tralie2018}; GUDHI 3.11.0 (bottleneck distance, landscapes); giotto-tda 0.6 \citep{Tauzin2021} for cross-checks; NumPy 1.26, SciPy 1.12, pandas 2.1, scikit-learn 1.4, statsmodels 0.14. An Apptainer/Docker container with pinned versions accompanies the release.

\paragraph{Synthetic exemplar.} A synthetic 22-agent swarm with seeded ring formations is included in the code release to enable teaching and reproduction without proprietary tracking data. Acceptance criterion: individual-scale $H_1$ presence rate within $\pm 3$~pp of the primary match ($96.0\%$), tactical-scale $H_1$ presence rate within $\pm 5$~pp of $12.0\%$, and at least one $H_1$ generator per frame recovered by closed-cycle identification for all frames with non-zero $H_1$. A pass/fail test implementing these checks ships in the code release.
